# V2.0.1 语音识别完整性修复

> 范围：只改前端识别结果处理（`public/app.js`、`public/style.css`），不改服务端和数据库，不更换识别引擎。
> 目标：浏览器识别出来的文字，不被我们自己的代码弄丢、弄重复、弄乱序；识别中断时让用户知道。

## 1. 背景：改之前的问题

识别引擎仍然是浏览器 Web Speech API。改之前，下面几个逻辑会让本来已经识别正确的内容丢失或重复：

| # | 旧逻辑 | 问题 |
| --- | --- | --- |
| 1 | `commitPause()`：停顿 0.9～1.6 秒就把 **interim 永久提交**（落库、翻译、朗读），之后靠 `dedupeFinal()` 按前缀剥掉 final 里「已提交过」的部分 | interim 会被浏览器修订，final 和已提交的 interim 不一致时，前缀匹配失败，出现重复或吞字；最近几次修复都在补这里 |
| 2 | final 判重：`finalSeen` 按 **文本内容 + 30 秒窗口** | 会议里 30 秒内说两次「好的」「对」「没问题」，第二次被当成重复吞掉 |
| 3 | final 比 interim 短时改用 interim | interim 是所有未定稿结果拼起来的，本来就经常比单条 final 长；等于把不稳定的文本塞进了正式稿 |
| 4 | 手动停止：先 `flushInterim()` 再 `rec.stop()` | `stop()` 之后浏览器通常还会送回最后的 final，于是 interim 和 final 各保存一份 |
| 5 | 自动重启：`onend` 后固定 120ms 重启，没有退避；`rec.start()` 失败被 `catch {}` 吞掉 | 网络错误时快速死循环；启动失败后界面仍显示「识别中」，实际已经不在识别，内容静默丢失 |
| 6 | 识别中断没有记录 | 用户不知道哪段时间没被记录 |

## 2. 方案

### 2.1 正式稿只来自 final；interim 只做临时显示

```
onresult
  ├─ final（i >= resultIndex 且未判重） ──► commitFinal() ──► 正式气泡：落库 / 朗读 / 大字幕
  └─ interim（完整 results 重建） ──► 「正在听」区
                                     └─ 实时模式停顿后 ──► 临时气泡（先翻译给人看，不落库、不朗读）
                                                            └─ final 到达时原地转正
```

- **临时气泡**（`showProvisional()`）：替代旧的 `commitPause()`。延迟体验不变（停顿后照样先出译文），但它只是显示，不进入正式记录。样式为半透明、译文斜体，标记「临时 · 等待浏览器定稿」，不显示「✎ 修正」。
- final 到达时，`commitFinal()` 把当前临时气泡原地转为正式气泡；如果临时翻译的原文和 final 完全一致，直接复用译文，不重复请求。
- 删除了 `lastCommitted`、`committedAt`、`dedupeFinal()`、`commitPause()`、`flushInterim()` 这一整套前缀匹配逻辑。
- 「整句」模式不生成临时气泡，只在「正在听」区显示 interim。

### 2.2 final 判重

`readSnapshot(event, run)`：

1. **只看 `i >= event.resultIndex` 的 final**。按规范，`resultIndex` 之前的结果没有变化，早已上报过。这一条解决了 Chrome 每次事件都带上全部历史 final 的问题。
2. **兜底：按内容 + 时间窗口判重**，应对部分浏览器把同一条 final 重新放到 `resultIndex` 之后上报的情况：
   - 长度 ≥ 8 个字符：10 秒内一字不差视为重复（长句短时间内被原样说两次的可能性很低）。
   - 长度 < 8：只在 1.5 秒内判重（「好的」「对」很可能被真的连说，宁可偶尔重复也不吞内容）。
3. 每个 final 单独提交，不拼接、不按前缀截断，也不再用 interim 替换 final。
4. 判重集合只在一次识别 run 内有效（每次 `start()` 重置）。
5. 每次被判重跳过都会记录 `final-dup` 事件，可在 `asrEvents()` 里核对。

### 2.3 停止顺序

`stopListening()`：先 `rec.stop()`，进入 `stopping` 状态，等浏览器送回最后的 final 并触发 `onend`；`onend` 里 `flushResidual()` 处理真正没定稿的残留。若 2 秒（`ASR_STOP_TIMEOUT`）内没有 `onend`，兜底收尾。

### 2.4 残留 interim：保留，标记待校对

浏览器到会话结束都没给 final 的 interim，不会再补发，丢掉就真丢了。`flushResidual()` 把它以「待校对」写入（落库，可用「✎ 修正」改）。如果没有 interim 但还挂着临时气泡（引擎撤回了临时结果），也按待校对保留。

### 2.5 重启状态机 + 退避

```
idle ──► starting ──► listening ──onend──► restart_wait ──► starting ...
              │                    └─用户停止──► stopping ──onend/超时──► stopped
              └─4 秒没有 onstart──► abort，计一次失败 ──► restart_wait
```

- 正常结束（含 `no-speech` 静音超时）：150ms 后重启。
- 出错（`network`、`audio-capture`、启动失败、启动超时等）：`failures++`，退避 500ms → 1s → 2s → 4s → 8s（上限）。收到任何识别结果后 `failures` 清零。
- `starting`/`listening` 状态下不会重复调用 `start()`；`InvalidStateError` 视为已在运行。
- `not-allowed` / `service-not-allowed`：直接停止并提示授权。
- 连续失败 ≥ 3 次时，状态栏显示「识别中断，N 秒后第 K 次重试…」。
- 被新实例替换的旧实例在 `onend` 里只做残留收尾，不再自行重启。

### 2.6 识别中断记录与提示

- 一次中断 = 从识别结束到之后第一个「健康 run」启动；重启后立刻又出错的 run 不算恢复，连续失败合并成一次。原因以中断期间最近一次错误为准（没有错误时为 `ended`）。
- 中断 ≥ 2 秒（`GAP_NOTICE_MS`）时，在记录里插入黄色提示行：「⚠ 时间 识别中断约 X 秒（原因），这段时间的发言可能没有记录」。提示只在页面显示，不落库、不导出。
- 控制台 `asrGaps()` 查看全部中断，`asrReport()` 里增加了中断次数和总时长。

### 2.7 其他

- 气泡改为**入队时就创建**（翻译仍串行），保证页面顺序与说话顺序一致；临时气泡也不会插到排队中的正式气泡前面。
- `asrEvents(n)` 增加 `run`、`kind`、`ri`（resultIndex）列，能看到 final 采纳、判重、残留、状态切换、错误等决策。
- 切换/清空会话后，挂在旧页面上的临时气泡不会被复用。

## 4. 验证

### 4.1 自动化（模拟识别事件）

用假的 `SpeechRecognition` 注入页面，脚本化地发送识别事件（服务端接口用 mock），验证了：

1. 已上报的 final 不重复提交（`resultIndex` 生效）。
2. 1.7 秒内连说两次「好的」，两条都保留。
3. 长句被重复上报（且落在 `resultIndex` 之后）仍判重。
4. 实时模式：停顿后出现临时气泡且不落库；final 到达后原地转正，只落库 final 一次。
5. 手动停止：停止时不提前提交 interim；随后到达的 final 只保存一份；状态回到「已停止」。
6. 会话结束时的残留 interim 以「待校对」保存，并自动重启。
7. 连续 `network` 错误时重启间隔递增；恢复后插入一条合并的中断提示。
8. `listening` 状态下重复调用 `startRecognition()` 不会重复 `start()`。

### 4.2 真机验证（需要人工做）

模拟事件只能验证我们自己的逻辑，**浏览器真实的上报行为需要在 Chrome / Edge 上实测**：

1. 打开控制台，正常开一段 10 分钟以上的会议。
2. 结束后执行 `asrEvents(200)`：
   - 搜 `final-dup`，确认被跳过的都是真正的重复上报；
   - 对照 `ri` 列，确认没有 final 落在 `resultIndex` 之前却是新内容的情况（如果有，说明该浏览器不遵守规范，需要调整 2.2 第 1 条）。
3. 执行 `asrGaps()` 和 `asrReport()`，记录中断次数和时长，作为后续评估专用 ASR 的基线。
4. 断网 10 秒再恢复，确认出现中断提示，状态栏有重试提示，恢复后继续识别。
5. 说一句话后立刻点停止，确认最后一句只出现一次。

## 5. 已知限制

- 仍然依赖浏览器识别引擎：引擎本身的错字、漏字、术语误识别，这次改动解决不了，需要第二阶段评估专用 ASR。
- 浏览器在重启间隙（正常约 150ms，出错时最长 8 秒）里听到的内容无法补回，只能提示。
- final 判重窗口是经验值。如果真机上发现长句被重复上报的间隔超过 10 秒，或短句重复上报间隔超过 1.5 秒，需要按 `asrEvents()` 的实测数据调整 `FINAL_REPEAT_LONG` / `FINAL_REPEAT_SHORT`。
- 临时气泡只在「实时」模式出现；朗读只读正式结果，所以朗读比临时译文晚一点出现。
